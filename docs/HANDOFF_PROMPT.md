## 1. What the project is

**PathPilot** (repo name `student-engagement-ecosystem`) is an AI-first student engagement platform, described as "SoFi for Indian students". It serves undergraduates and young professionals in India who plan a master's or MBA abroad (USA, UK, Canada, Germany, Australia, Ireland, Netherlands) or in India. The product funnel is **awareness, engagement, trust, then education-loan conversion**.

It was built as a hackathon prototype by one developer in 4 days. Judges score innovation, depth of AI use, UX and stickiness, NBFC-aware conversion thinking, and prototype quality. Bonus points go to a zero-human AI growth loop and a live deployment. The prototype is **deployed publicly for real testers**.

- Repo: https://github.com/poorvi-16/student-engagement-ecosystem (branch `main`)
- Frontend (Vercel): https://student-engagement-ecosystem.vercel.app
- API (Render): https://pathpilot-api-n4ox.onrender.com (`/health` shows model and storage status)
- The Render free instance sleeps when idle; the first request takes 30 to 60 seconds.

**Everything about lending is simulated.** The lenders, offers, credit bureau, lender system and sanction letters are fictional, generated by our own code, and labelled as simulated in the UI. WhatsApp and email nudges are mocks; nothing is sent. Keep that honesty when you change anything.

## 2. Tech stack

- **Frontend** `frontend/`: Next.js 15 (App Router) with TypeScript, Tailwind v4, Recharts, supabase-js. Deployed on Vercel from the `frontend/` root.
- **Backend** `backend/`: FastAPI, SQLModel, Alembic, APScheduler, scikit-learn, httpx. Deployed on Render as a Docker service (Singapore, free plan, exactly one instance), auto-deploy on push. `backend/start.sh` runs `alembic upgrade head` before starting uvicorn.
- **Database, auth, storage**: Supabase. Postgres (use the **Session pooler** URL), Supabase Auth (email and password primary, magic link and Google secondary; the project signs tokens with ES256 and the backend verifies via JWKS), and a private Storage bucket `loan-docs` that the backend creates on first upload. SQLite is used only in tests.
- **LLMs, free tiers only** (the owner chose not to buy an API key): Gemini first (`gemini-flash-lite-latest`, `gemini-3.5-flash`, reasoning effort "minimal", through Google's OpenAI-compatible endpoint), then Groq (`openai/gpt-oss-20b` and `gpt-oss-120b`) as automatic fallback. Free quotas are per model and shared by all users. Anthropic is supported as an optional paid provider for structured calls but is not configured. Gemini is the only provider that can read images (document extraction).
- **ML**: scikit-learn gradient boosting with monotonic constraints. Two models, committed as `.pkl` plus `.json` in `backend/app/ml/models/`: `admit-v1` (admission chance, AUC about 0.83 on held-out programs) and `lead-v1` (loan-conversion likelihood, AUC about 0.80). Both are trained on **synthetic** data and the product says so. `scikit-learn==1.9.1` and `numpy==2.5.4` are pinned because the pickles must load with the version that trained them.
- **Scheduling**: APScheduler runs inside the API process (relies on the single instance). Jobs: delete expired loan documents every 6 hours, and the growth orchestrator daily at 10:00 IST.

## 4. Core design principles (do not break these)

1. **Profile is the single source of truth.** The onboarding quiz creates a `StudentProfile`; every module reads it. Changing an upstream output shape breaks downstream screens.
2. **Rules decide money, ML scores, the LLM explains.** Loan eligibility, FOIR, offers, EMI, APR, Section 80E, ROI and timeline dates are pure code in `app/rules/` and are unit-tested. An LLM must never compute money or decide eligibility.
3. **Every LLM call goes through `app/llm.py`**: `llm.parse(session, user, feature=, system=, prompt=, output=PydanticModel, tier="fast"|"smart", images=)` for structured output and `llm.chat(...)` for tool loops. It tries providers and models in order, enforces the per-user daily limit, the global daily cap, the monthly budget and the admin pause switch, and logs to `llmusage`. It raises `LLMUnavailable`; **every feature must catch it and fall back to non-AI output**. Cache deterministic results in `AiCache`. Never send names or emails to a model. Tests never call real providers.
4. **Events and XP.** Record user actions with `events.log_event(session, user, type, payload, xp=, once=)`. Growth (streak, stage, badges, nudges, lead score, funnel) is derived from the `event` table.
5. **Row Level Security on every table.** Supabase exposes `public` tables through its REST API to the anon key. Every new table's migration must run `ALTER TABLE "<name>" ENABLE ROW LEVEL SECURITY` (see existing migrations; guard with a Postgres dialect check). The backend connects as the owner and bypasses RLS.
6. **Multi-user isolation.** Every query is scoped by the `user_id` from the verified JWT. By-id routes must return 404 for another user's rows. `tests/test_hardening.py` checks this across modules; extend it for new modules.
7. **Privacy.** Aadhaar is stored as its last 4 digits only and its image is never stored. Uploaded files go to the private bucket, are viewed through 5-minute signed URLs, and are deleted after 30 days. Three consents (KYC, bureau, DPDP) are required to submit a loan application. Students can export (`GET /me/export`) and delete (`DELETE /me`) all their data; deletion is generic over any table with a `user_id` column.
8. **Simulated finance is always labelled.**

## 5. Modules and how they work

- **Onboarding quiz and profile strength** (`api/me.py`, `rules/profile_strength.py`): `PUT /me/profile` creates or updates the profile (+100 XP once). `GET /me` also updates the daily streak (+5 XP per day) and refreshes the journey stage and interest tags.
- **Career Navigator** (`services/navigator.py`, `api/navigator.py`): filters the catalog by country, field and level, scores admit chance with the ML model (batched), takes cost, payback and funding gap from `rules/roi.py`, buckets Ambitious (<25%), Target (<60%), Safe, one program per university. The LLM only writes the "why" text. Shortlist table `shortlist`.
- **Admit model and program page** (`ml/`, `api/programs.py`, `/programs/[id]`): what-if sliders and an ROI calculator. Changing model `FEATURES` means bumping `MODEL_VERSION` and retraining with `python -m app.ml.train`.
- **Mentor** (`services/mentor.py`, `rag/kb.py`): RAG with BM25 over the curated guides plus tools (`search_knowledge`, `find_programs`, `analyze_program`, `estimate_loan`) that call the same service functions as the REST routes. Answers carry `[S1]`-style citations.
- **Timeline** (`rules/timeline.py`, `services/timeline.py`): dated tasks from intake, program deadlines, tests, SOP, visa steps and loan; one LLM call adds a summary and tips but never changes dates. Tasks have stable keys so regeneration keeps ticks.
- **SOP reviewer** (`rules/sop.py`, `services/sop.py`): rule checks plus an LLM rubric. Quotes must appear verbatim in the SOP; rewrites may use only facts from the SOP.
- **Visa mock interview** (`rules/visa.py`, `services/visa.py`): question banks for 7 countries, per-answer LLM evaluation (rule-based fallback), at most 2 follow-ups, readiness score. The frontend supports speech in and out.
- **Loan planner** (`rules/loan.py`, `services/loan.py`, `/loan`): soft eligibility across fictional products (country, university tier, co-applicant income, collateral, margin, FOIR), pricing with visible premiums, KFS-style APR, moratorium with simple interest, year-by-year schedule, Section 80E (old tax regime only).
- **Loan copilot** (`services/loan_application.py`, `services/documents.py`, `rules/loan_docs.py`, `mocks/cibil.py`, `mocks/nbfc_los.py`, `/loan/apply`): one active application per student, documents read by Gemini vision, deterministic cross-checks, mock bureau and lender system, a tracker whose stages are revealed over about 10 minutes, ending in a provisional simulated sanction.
- **Growth layer** (`services/growth.py`, `rules/gamification.py`, `rules/nudges.py`): levels, streaks, 15 badges, ranked next-best-action nudges (loan steps first, max 3 active), referral codes (+50 for the friend, +100 for the referrer), opt-in public share card at `/card/[code]` with an OG image, derived journey stage (explorer, shortlister, applicant, admitted, funding).
- **Nudge A/B** (`rules/ab.py`): each nudge has a copy variant A (control) or B (benefit-led); even split until 20 exposures each, then about 80% the better one; z-test readout.
- **Content agent and Discover** (`agents/content.py`, `rules/feed.py`, `api/content.py`): turns each knowledge-base guide into a public guide, a reel script and a LinkedIn post using one LLM call grounded only in that guide's text (fallback: assemble from the text). Posts keep all source URLs shown as external "read the full source" links. Discover ranks by interests, stage, recency and views with a variety penalty, and groups posts into aspects (visas, careers, tests and applications, money, life abroad, planning, countries). Public SEO pages: `/guides`, `/guides/[slug]`, sitemap, robots. UTM tags are captured and reported once as `signup_attribution`.
- **Lead score** (`ml/lead.py`, `services/leads.py`): 19 behaviour features, monotonic gradient boosting, "why" via batched feature removal. `HOT_THRESHOLD` is 0.25.
- **User simulator** (`agents/simulator.py`): synthetic students flagged `is_simulated`, with back-dated events and hidden traits (a planted 1.4x lift for copy B). Used to give the loop data. Never present simulated numbers as real.
- **Growth orchestrator** (`agents/orchestrator.py`): one run is simulate, learn, acquire, nurture, convert, measure; each step is timed and logged to `agentrun`; a failing step does not stop the run. Convert sends a loan-copilot nudge to hot leads.
- **Admin Agent Console** (`api/admin.py`, `/admin`): funnel, daily trend, agent run log, lead scores, A/B results, content performance, AI usage, mock message log, feedback inbox, simulation controls, AI pause switch. Admin role comes from `ADMIN_EMAILS`.
- **Safety** (`ratelimit.py`, `llm.py`, `api/feedback.py`): rate limits (AI actions 20/min per user, public pages 60/min per IP, others 240/min per identity, 600/min per IP), global daily AI cap (`GLOBAL_DAILY_LLM_CALLS`, default 1500), admin pause, feedback button, `/privacy`, footer disclosure, optional Sentry.

```bash

The owner's machine is Windows 11 with Git Bash and PowerShell; paths contain spaces-free but long names, and a local pytest run can hang if memory is low (single-thread BLAS is set to avoid that).

## 9. Working conventions (follow these)

- Build in small steps. After each completed step, run tests, lint and type-check, then commit and **push to `origin main`** so a saved version always exists.
- Commit messages: imperative subject of at most 72 characters naming the step; body grouped by Backend, Frontend, Database, Tests, Docs, noting new migrations, env vars and manual steps. Before committing, confirm no secrets are staged: `git ls-files --cached | grep -E "\.env($|\.local)"` must print nothing. Never force-push or rewrite pushed history.
- Keep `CLAUDE.md` updated whenever architecture or behaviour changes.
- For a new table: add the model, generate an Alembic migration, review it, add RLS, add tests, and make sure `services/account.delete_user_data` covers it (it does automatically if the table has a `user_id` column).
- For a new endpoint: put logic in `services/` or `rules/`, scope by `user.id`, log an event if it is a user action, add tests (including a cross-user 404 test), and update the frontend page.
- For a new LLM feature: use `llm.parse`, define a Pydantic output model with field descriptions, cache if deterministic, always provide a non-AI fallback, and test with a monkeypatched `llm.parse`.
- Be honest in the product: label anything simulated, cite sources, never invent facts, and never claim a result you have not verified. When you report back, say what you ran and what you could not check.
- Do not add dependencies lightly; the Render free instance has 512 MB of memory.
